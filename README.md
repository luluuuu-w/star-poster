# 明星海报生成器

上传一张人物照片，自动分析配色与构图并生成海报；生成后可以任意修改，也可以自己画装饰、自己设计排版并存成模板复用。

**纯前端应用，零后端。** 照片和作品只存在你自己的浏览器里，不会上传到任何服务器。

---

## 快速开始

```bash
npm install
npm run dev      # 开发服务器
npm run build    # 生产构建
npm run preview  # 预览生产构建
npm test         # 单元测试
```

首次 `npm install` 后如果提示 esbuild 的安装脚本未执行，运行 `npm approve-scripts esbuild && npm rebuild esbuild`。

## 功能

**自动生成** —— 传图后自动完成三件事：从照片提取配色、识别人物主体与可用留白、从版型库里挑最合适的一套套用。全部在浏览器本地算完，秒出，离线可用。

**修改** —— 画布上直接拖拽、缩放、旋转；图层面板管理层级与显隐；属性面板改颜色、字体、滤镜、遮罩；4 套配色方案一键切换；10 套版型随时换；36+ 预设装饰点击插入。撤销重做 50 步。

**创作工作室** —— 画笔/直线/矩形/椭圆/多边形画自己的装饰，或导入 PNG·SVG 素材，存成可复用的装饰；摆放槽位设计自己的版型，存成模板并参与自动推荐。

**文字** —— 字体、字号、字重、颜色（纯色/渐变）、字间距、行高、对齐、描边、阴影、底色块、竖排中文。

**导出** —— PNG / JPG，1x·2x·3x，含小红书竖图、竖屏故事、方图、A3 印刷等尺寸预设。

## 两条贯穿全局的设计约定

理解这两条，代码基本就能读下去了。

### 1. 几何一律用相对值

所有位置和尺寸都是 0~1 的比例（相对画布宽高），字号和线宽相对画布短边。像素只在渲染那一刻才出现。

这带来三个好处：同一份模板能套用到任意画布尺寸；导出 2x/3x 只需换 `pixelRatio`；换画布尺寸不用重排。

### 2. 颜色可以引用配色变量

颜色字段既能写死 `#RRGGBB`，也能写 `@primary` 这样的 **palette token**。渲染时由 `resolveColor()` 解析。

这是「一键换配色整张海报联动」的实现基础 —— 换方案时只改 `palette.roles`，所有引用 token 的元素自动跟着变。**内置模板和内置装饰一律只用 token，不写死颜色**（有单元测试守着这条）。用户在工作室画装饰时，选的也是「色位」而不是具体颜色，色位再绑定到 token。

`accent`（点缀）和 `accentText`（点缀色文字）是两个独立角色，这不是冗余：点缀色当色块填充时对比度拉太高会刺眼、也会丢掉原本的色彩感觉，当小字用时对比度不够又看不清。两种用途要求相反，所以文字用途单独派生一个过了 AA 的变体。

## 关键算法

### 配色提取（`core/color/`）

1. 图片降采样到 96×96，RGB → **OKLab**。用 OKLab 而不是 RGB/HSL，是因为它的欧氏距离≈人眼感知差异，同样的 k-means 出来的主色明显更贴合直觉。
2. **k-means（k=6）**，k-means++ 初始化，**固定随机种子** → 同一张图每次结果完全一致，重开作品配色不会莫名其妙变了。
3. 按 `占比 × 彩度` 分配语义角色。纯看占比会选中大片的灰墙白背景，加上彩度权重才能选到「这张照片给人的印象色」。
4. **对比度兜底**：文字色与底色对比度不足 4.5:1 就沿 OKLab 的 L 轴二分调整到达标。这一步保证自动生成的文字永远看得清。
5. **色域回收**：明暗两端 sRGB 色域会急剧收窄，硬夹 RGB 三通道会改变色相（暖白会变成青白）。所以 `oklabToHex()` 会先降彩度把颜色拉回色域，再转换。
6. 产出 4 套变体：原色 / 高对比 / 柔和 / 单色。

### 主体识别（`core/vision/`）

不依赖任何模型文件，纯图像处理，三路信号加权：与全图均值的 OKLab 色彩距离、Sobel 边缘密度（经盒式模糊摊成区域）、中心偏上先验。

取显著性 top 15% 像素，用行列投影的分位数求包围盒（不用极值，否则一个孤立噪点就能把框拉满全图）。反过来求低信息量区域作为「可安全放文字的留白」，编辑器里点「分析视图」能看到。

自动裁切以显著性重心为焦点开窗，避免把人脸切掉 —— 这是自动出稿最容易翻车的地方。

### 版型匹配（`core/layout/match.ts`）

四项加权打分：宽高比契合（0.3）+ 主体落点（0.3）+ 文字区留白（0.3）+ 色调偏好（0.1）。用户自建模板和内置模板平等参与打分。

## 数据存储

IndexedDB，五张表：`docs` / `thumbnails` / `assets` / `templates` / `decorations`。缩略图单独一张表，避免每次读文档都多拖几百 KB。

存储层抽象成 `core/store/Store.ts` 接口，将来要接后端只需写一个 `RemoteStore`，UI 层一行不用改。

**没有云端**，所以「我的库」里提供了导出/导入 JSON 备份。换设备或清理浏览器数据前记得导出。

## 字体

当前用的是**系统字体栈**（苹方 / 微软雅黑 / 宋体 / 楷体等），在中文系统上开箱可用，零下载体积。

`core/fonts/registry.ts` 和 `loader.ts` 已经把自托管字体的加载逻辑写好了。要换成自托管的开源中文字体：

1. 挑可免费商用的字体（思源黑体、思源宋体、得意黑都是 SIL OFL；站酷系列免费商用）。
2. 用 `fonttools` 之类的工具做子集化 —— 完整中文字体动辄 5-10MB，必须子集化。
3. 放进 `public/fonts/`，在 `registry.ts` 里给对应 `FontDef` 的 `files` 填上 `{ weight, url }`。

剩下的按需懒加载逻辑不用改。

> **导出前必须 `await document.fonts.ready`**。Konva 用 Canvas `measureText` 测量文本宽度，字体没加载完就渲染会用回退字体测量，导出图的换行位置和实际预览对不上。`core/render/export.ts` 已经处理了这一点。

## 测试

**单元测试**（226 个，`npm test`）覆盖纯函数里最容易出错的部分：OKLab 往返转换与色域处理、k-means 的确定性、WCAG 对比度计算与修正、配色角色分配的不变量（任何照片 × 任何变体，文字对比度都达标）、显著性分析、版型打分与实例化、渐变轴几何、笔迹简化与命中检测、模板文字的保留、文档版本迁移。

**端到端验证**（`node scripts/e2e.mjs <端口>`，需先起 dev server）用真实浏览器跑完整流程：三张风格不同的合成照片 → 自动分析 → 断言配色调性和色相与照片相符、文字对比度达标 → 画布真的画出了内容 → 拖拽/缩放/插入/撤销 → 走 UI 下载 PNG 并解析文件头校验尺寸 → 刷新验证持久化 → 工作室画装饰存盘 → 验证自建装饰和模板确实能在编辑器里用上。

**版型画廊**（`node scripts/gallery.mjs <端口>`）把同一张照片套进全部 10 套版型各截一张图。结构化断言只能保证「产出了图层、几何合法」，看不出排版是不是真的成立 —— 这个脚本把结果摊开，肉眼扫一遍就能发现问题。前面两个真实 bug（渐隐层的硬边、换版型丢文字）就是这么发现的。

这部分是单元测试覆盖不到的：Konva 渲染、Web Worker、IndexedDB、字体测量、真实鼠标事件。截图落在 `e2e-out/`。

`scripts/fixtures.mjs` 用一个最小 PNG 编码器合成测试图，不依赖外部图片资源。

## 已知限制

- **橡皮是整条删除笔画**，不是擦掉局部像素。装饰必须是矢量的才能跟着配色变色，像素级擦除和这个目标不兼容。
- **文字编辑用弹窗**而非画布内联。画布内联要在 Konva 上叠一个绝对定位 textarea 并同步字体、字号、旋转、缩放，边界情况很多；弹窗改多行文字反而更顺手，右侧属性面板也随时能改。
- **竖排中文是按字符拆行模拟的**，标点符号不会做竖排专用的旋转。
- 主体识别是纯显著性算法，**不是人脸检测**。多人合影或主体与背景色调接近时可能框不准，可以在属性面板手动微调裁切。
